## Workstream A — Generation stats (tokens/sec + time-to-first-token)

No stats infrastructure exists today. Build it once in the common funnel, `StreamProcessor`, which all backends already stream through.

1. **`GenerationStats` struct** (new, `Services/Inference/`): `timeToFirstToken: TimeInterval`, `totalDuration: TimeInterval`, `outputTokens: Int?` (exact when the runtime reports it, else nil), `deltaCount: Int` (fallback approximation), computed `tokensPerSecond`.
2. **`StreamProcessor`** accumulates timing (stream start, first `.textDelta`/`.thinkingDelta`, stream end) and delta count; the `.done` event carries the stats (`case done(GenerationStats)`). Exact token counts pass through where cheap: llama.cpp knows generated-token counts (`LocalLlamaRuntime`/`LocalLlamaContext`); MLX's `GenerateResult` reports tokens/sec natively.
3. **Persistence + display**: optional `stats: GenerationStats?` on `ChatMessage` (Codable, backward-compatible decode — mirror how `citations` was added). Subtle one-line footer on assistant bubbles ("12.4 tok/s · 0.8s to first token"). `AppTheme` colors only.
4. **Settings toggle**: `AppSettings.showGenerationStats` (default **on**), surfaced in Settings; existing-settings decode defaults gracefully.
5. **OSLog instrumentation**: per-generation tokens/sec from `LocalLlamaContext` via OSLog so the 0.3.1 on-device benchmark can compare flash-attention on/off without a debugger.

## Workstream B — Faster model switching

1. **Search↔chat context reload**: `LocalLlamaRuntime.ensureContext()` fully reloads when `maxGeneratedTokens` changes (search 2048 vs chat 1024). Make the generation cap a per-call parameter instead of a context-creation parameter so toggling search no longer reloads the model. Budgets still come from `InferenceBudget`.
2. **Eager load on model select**: kick off loading when the user picks a model from the chat header dropdown in `ChatView` (still routed through `RuntimeMemoryCoordinator.prepareForRuntime(...)`; cancel cleanly if the user switches again before load completes).

Invariant: this workstream must not change *when* runtimes are unloaded, only avoid *redundant* reloads — runtimes never co-occupy memory.

## Workstream C — UI polish pass (bounded checklist)

- Empty states (no chats yet, no models installed, no search results in history).
- Error message copy for common failures (model load failure, download stall, tool-call limit).
- Accessibility labels on composer buttons and model-picker rows.
- Download-progress presentation in `ModelLibraryView`.
- Composer modifiers go in the `composerPresentationModifiers` extension (type-checker fragility).

All polish uses `AppTheme`; new adaptive colors extend `AppTheme` (light + dark variants).
